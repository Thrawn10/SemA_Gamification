# Agent setup (OpenCode)

This project is prepared for spec-driven work with AI coding agents. **OpenCode is the primary
tool.** The role definitions are tool-neutral Markdown, so another tool can reuse them, but only the
OpenCode adapters are maintained.

## Layout

| Path                                                                  | Purpose                                                                          |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `AGENTS.md`                                                           | Shared project instructions, conventions, workflow, definition of done           |
| `docs/agents/`                                                        | Canonical role definitions for the 10 subagents                                  |
| `.opencode/agents/`                                                   | Thin OpenCode adapters: description, mode, permissions, pointer to the role file |
| `.opencode/commands/`                                                 | Orchestration commands: `/build-from-spec`, `/next-task`, `/review-feature`      |
| `.opencode/skills/`                                                   | Project skills: `spec-intake`, `angular-conventions`                             |
| `.agents/skills/`, `skills-lock.json`                                 | Official Angular skills installed by the setup script; generated, gitignored     |
| `opencode.json`                                                       | Project config: Angular CLI MCP server, permissions, instructions                |
| `docs/spec/SPEC.md`                                                   | Full specification (single source of truth)                                      |
| `docs/spec/requirements.md`, `work-breakdown.md`, `open-questions.md` | Generated by `spec-analyst`                                                      |
| `docs/PROGRESS.md`                                                    | Task status, updated after every task                                            |
| `docs/architecture/DECISIONS.md`                                      | ADRs written by `architect`                                                      |
| `docs/angular/best-practices.md`                                      | Official Angular guidance, fetched by `scripts/setup-angular-agents.*`           |
| `scripts/setup-angular-agents.ps1` / `.sh`                            | Downloads the official guidance and installs official skills                     |

The old `angular-agents-bundle.md` is the source bundle this setup was split from. Do not edit it as
the working configuration; edit the files above.

## Agents

| Agent                    | Purpose                                                            | Writes code?  |
| ------------------------ | ------------------------------------------------------------------ | ------------- |
| `spec-analyst`           | Requirements, work breakdown, open questions                       | docs only     |
| `architect`              | Architecture, routing, state/data strategy, ADRs, workspace config | docs + config |
| `design-system-engineer` | Tokens, theming, shared UI components                              | yes           |
| `ui-component-developer` | Presentational standalone components                               | yes           |
| `feature-developer`      | Feature routes, pages, services/stores, HTTP, forms, guards        | yes           |
| `test-engineer`          | Vitest/TestBed/harness tests, coverage                             | tests only    |
| `a11y-reviewer`          | Accessibility audit                                                | no (reports)  |
| `code-reviewer`          | Correctness, Angular conventions, maintainability                  | no (reports)  |
| `performance-auditor`    | Bundle, change detection, loading performance                      | no (reports)  |
| `docs-writer`            | README, component docs, handover docs                              | docs only     |

The main session is the orchestrator. Subagents cannot spawn other subagents, so the orchestration
lives in the commands and in the main conversation. Because the adapters use `mode: all`, the same
roles also appear in OpenCode's agent switcher and can be selected directly.

## How OpenCode discovers the files

- Agents: Markdown files in `.opencode/agents/<name>.md`. The filename is the agent name. The
  frontmatter sets `description`, `mode: all` and optional `permission` rules. `mode: all` makes the
  role both selectable in the agent switcher and available to the orchestrator as a subagent; a
  `mode: subagent` role would only be reachable through delegation.
- Commands: Markdown files in `.opencode/commands/<name>.md`. The filename is the command name.
- Skills: `.opencode/skills/<name>/SKILL.md` with `name` and `description` frontmatter.
- Project instructions: `AGENTS.md` is loaded automatically. `opencode.json` also adds
  `docs/angular/best-practices.md` to the instructions.
- MCP: `opencode.json` → `mcp.servers` starts the Angular CLI MCP server via `npx`. It provides
  `get_best_practices`, `search_documentation`, `list_projects`, `run_target`, `devserver_*`,
  `onpush_zoneless_migration` and `ai_tutor`.

Check what OpenCode loaded with:

```sh
opencode debug agents
opencode debug config
```

Command list and skill list are also available from the running server:

```sh
opencode api get /api/command
opencode api get /api/skill
```

## Usage

Start OpenCode in the repository, then use the commands:

- `/build-from-spec intake` — turn `docs/spec/SPEC.md` into requirements, work breakdown and open
  questions.
- `/build-from-spec architecture` — decide structure, data layer, state, UI foundation; write ADRs.
- `/build-from-spec foundation` — build tokens, theme and shared components.
- `/build-from-spec features` — run the feature loop until the work breakdown is done.
- `/build-from-spec quality` — run the quality gate.
- `/build-from-spec docs` — write README, overview, component docs and handover.
- `/next-task [task-id]` — implement, test and review exactly one task.
- `/review-feature [feature]` — code, accessibility and performance review, plus test coverage.

You can also delegate directly; mention the agent name in your prompt, e.g. "use `architect` to
decide the routing tree". The agents read `AGENTS.md`, their canonical role file and
`docs/PROGRESS.md` before starting.

## Permissions

The adapters make the read-only roles read-only:

- `a11y-reviewer`, `code-reviewer`, `performance-auditor`: `edit: deny`
- `spec-analyst`, `docs-writer`: `bash: deny`
- Builders and the architect keep edit and shell access.

Project-wide permissions in `opencode.json` ask before reading `.env` files and before `git push`,
and deny `rm -rf`. Agent-level rules are merged on top of the project rules.

## Models

No model is pinned in the agent adapters, so every agent uses the model of the current session. To
pin one, add a `model:` line to the adapter frontmatter using OpenCode's `provider/model` form.

## Official Angular resources

Run one of:

```sh
pwsh scripts/setup-angular-agents.ps1
bash scripts/setup-angular-agents.sh
```

The script downloads Angular's official best-practices file into `docs/angular/` and installs the
official `angular-developer` and `angular-new-app` skills via `npx skills add`. The repository
already contains the downloaded guidance and the `angular-developer` skill; re-run the script to
refresh them. The Angular CLI MCP server is configured in `opencode.json` and starts via `npx` (it
also needs network access the first time).

## Adding or changing an agent

1. Edit the canonical role in `docs/agents/<name>.md`.
2. If it is a new agent, add `.opencode/agents/<name>.md` with the same `name`, a `description`,
   `mode: all` and the narrowest permissions that still let it do its job.
3. Add the agent to the roster in `AGENTS.md`, `docs/agents/README.md` and this file.
4. Restart or reload OpenCode, then check `opencode debug agents`.

Do not put long role instructions only in the adapter; the adapter stays thin so the role can be
reused outside OpenCode.

## Claude Code compatibility

`CLAUDE.md` still points at `AGENTS.md`, but no `.claude/` adapters are maintained. If Claude Code is
used, it can read `AGENTS.md` and the canonical role files directly; create `.claude/agents/` only
if that tool is adopted again.
